# Места

«Места» — учебное веб-приложение для бронирования билетов на мероприятия из [DevOps-роадмапа](../../roadmap.md).

## Возможности

- Афиша показывает карточки событий с датой, площадкой, описанием и остатком мест.
- Посетитель выбирает от 1 до 8 билетов и получает уникальный номер брони. Срок удержания по умолчанию составляет 15 минут или до начала мероприятия, если оно наступает раньше.
- По номеру можно узнать статус и отменить активную бронь. После отмены или истечения срока места возвращаются в продажу.
- Воркер обрабатывает истечение срока и имитирует отправку подтверждения. Результат имитации хранится в поле `confirmation_at`.
- Приложение работает с синтетическими мероприятиями. Номер брони даёт доступ к просмотру и отмене, поэтому сохраняйте этот номер у себя. Бронь временно удерживает места.

## Состав

| Путь | Назначение |
| --- | --- |
| `app/frontend/` | React, Vite, русскоязычный интерфейс |
| `app/api/` | HTTP API на Go |
| `app/worker/` | Go-воркер, опрашивает PostgreSQL каждые две секунды |
| `app/internal/booking/` | Транзакции, SQL-миграции и демонстрационные данные |
| `deploy/` | Docker Compose, Nginx, smoke-тест |
| `infra/` | Каталог инфраструктуры для следующих этапов |
| `load/` | Сценарии k6 для обычного трафика, всплеска и последнего места |
| `docs/` | Архитектура, решения, инструкции, инциденты и эксперименты |

PostgreSQL хранит мероприятия, остатки и брони. Условный `UPDATE` уменьшает остаток в одной транзакции с созданием брони. При конкуренции за последнее место условие проверяется после освобождения блокировки строки. Отмена и истечение срока меняют статус и возвращают места атомарно. Статус `expired` появляется после обработки воркером, поэтому при остановленном воркере освобождение мест задерживается.

Клиент задаёт `Idempotency-Key` при создании брони. Повтор успешного запроса с тем же ключом и параметрами возвращает исходный ответ `201` с тем же идентификатором. Для текущего статуса служит отдельный GET. Повтор ключа с другим мероприятием или количеством даёт `409`. Воркер использует блокировку `SKIP LOCKED`, поэтому несколько экземпляров могут работать с одной базой.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка процесса API |
| `GET /ready` | Проверка соединения с PostgreSQL |
| `GET /api/events` | Предстоящие мероприятия и остатки |
| `POST /api/bookings` | Создать бронь с заголовком `Idempotency-Key` и JSON-полями `event_id`, `quantity` |
| `GET /api/bookings/{id}` | Текущее состояние брони |
| `DELETE /api/bookings/{id}` | Отменить бронь и вернуть её текущее состояние |

API запускает версионированные миграции при старте. При `SEED_DEMO=true` он добавляет четыре демонстрационных события. Повторный запуск сохраняет существующие брони и остатки.
