# Локальный запуск и проверки

## Разработка без Docker

Нужны Go 1.24+, Node.js 20.19+ и PostgreSQL 16+. В PostgreSQL создайте пустую базу `tickets` и пользователя с правами создавать в ней таблицы. В двух терминалах из `app/` запустите API и воркер с URL этой базы.

```bash
export DATABASE_URL='postgres://tickets:ВАШ_ПАРОЛЬ@localhost:5432/tickets?sslmode=disable'
SEED_DEMO=true HTTP_ADDR=127.0.0.1:8080 go run ./api
```

```bash
export DATABASE_URL='postgres://tickets:ВАШ_ПАРОЛЬ@localhost:5432/tickets?sslmode=disable'
go run ./worker
```

В третьем терминале из корня проекта:

```bash
cd app/frontend
npm ci
npm run dev
```

Vite открывает интерфейс на [http://localhost:5173](http://localhost:5173) и проксирует запросы API на порт 8080.

## Истечение срока

При запуске стенда задайте `BOOKING_TTL=5s`. Создайте бронь в интерфейсе и подождите несколько секунд. Проверьте статус брони и обновите афишу. После обработки воркером статус изменится на «Истекла», а количество мест восстановится. Для smoke-теста и нагрузки используйте обычный срок 15 минут.

## Нагрузочные сценарии

С установленным k6 выполните из корня проекта:

```bash
k6 run load/tickets.js
PROFILE=spike k6 run load/tickets.js
PROFILE=last k6 run load/tickets.js
```

Обычный профиль сочетает каталог с периодическим бронированием. Всплеск увеличивает число виртуальных пользователей до 40. Эти профили отменяют созданные брони. Профиль `last` отправляет 20 попыток на событие «Открытая репетиция» с одним свободным местом и проверяет, что ровно одна попытка получила `201`. Место удерживается до истечения брони. URL локального стенда можно переопределить через `BASE_URL`.
